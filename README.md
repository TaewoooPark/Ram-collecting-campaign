# 램모으기 운동

[웹에서 램모으기 운동 참여하기](https://taewooopark.github.io/Ram-collecting-campaign/)

은행 접수창구의 개인 체험 웹 작품. 새 브라우저는 첫 사진에서 시작한다. 실제 또는 가상으로 기부할 때마다 다음 장면이 열리고, 60번째 사진에 도달한 뒤에도 계속 접수할 수 있다. 이전 30장판의 방문자는 마지막으로 봤던 사진에서 이어 간다.

## 실행

Node.js 22.13 이상에서 이 폴더의 `npm start`를 실행한 뒤 [접수창구](http://127.0.0.1:4173)를 연다. 별도 패키지 설치는 필요 없다. 같은 무선망에서 휴대폰으로 확인할 때는 `HOST=0.0.0.0 npm start`로 실행하고 컴퓨터의 사설 아이피와 같은 포트를 연다. `PORT`로 포트를 지정한다. 장착 램 힌트를 지원하는 브라우저라도 일반 사설망 HTTP에서는 값이 생략될 수 있다.

## 접수와 반환

기부 한 건은 4, 8, 16메가바이트 중 고르며 메가바이트당 1,000,000바이트다. **더 기부하기**로 여러 건을 이어서 맡길 수 있다. 확인할 때마다 선택한 양의 버퍼 전체에 실제 데이터를 쓴다. 탭에 보관하는 한도는 64메가바이트이며, 한도에 도달하면 오래된 4메가바이트 단위 버퍼부터 재사용한다. 접수증에서 다시 쓸 양을 미리 알 수 있다. **돌려받기**, 탭 숨김, 페이지 이탈 시 모두 반환한다. 이미지 디코딩과 운영체제의 회수 시점 때문에 작업 관리자 전체 사용량의 차이는 버퍼 크기와 다를 수 있다.

오른쪽 위 **가상 기부**는 기부용 메모리를 할당하거나 쓰지 않고 그림과 횟수만 진행한다. 이미 맡긴 실제 램은 직접 돌려받거나 탭을 떠날 때까지 유지한다.

왼쪽 위 **초기화**는 현재 탭의 모든 기부 버퍼를 즉시 해제하고 개인 접수 기록과 그림을 처음으로 돌린다. 같은 브라우저의 다른 창도 초기화를 받아 보유 중인 버퍼를 놓는다. 처음 상태에서 다른 사람의 방문 수를 더하는 과정은 없다.

서버는 정적 이미지와 웹 파일만 전송한다. 체험 기록은 브라우저의 IndexedDB에 저장돼 같은 브라우저와 주소에서 다시 방문하면 이어진다. 다른 브라우저·프로필·기기는 각각 따로 시작한다. 저장소가 막힌 환경에서는 이용 가능한 로컬 저장소나 열린 탭의 메모리를 쓴다. `npm test`로 메모리 보유량과 개인 체험·초기화 규칙을 검증한다.

## 그림과 서체

1~30번은 창구에 쌓인 기판이 서울의 산맥과 달의 고리가 되기까지의 기록이다. 31~60번은 그 뒤를 상상한 풍자 사진이다. 네 사람이 은행에 램을 청하러 오고, 동네에서는 램으로 수영하고 한옥을 짓는다. 달행 열차를 지나 마지막에는 이 세계가 담긴 기판 한 장이 다시 창구 저울에 오른다. [1~30번 모아보기](시안/서른-장면-모아보기.jpg) · [31~60번 모아보기](시안/31-60-모아보기.jpg)

새 장면의 접수 손동작과 저울은 같은 자리에서 이어진다. 다음 사진을 읽는 동안 현재 사진을 유지하고, 준비되면 두 사진을 포개 천천히 바꾼다. 연달아 기부하면 중간 장면을 순서대로 짧게 보여 준다. 기기의 동작 줄이기 설정에서는 곧바로 바뀐다. [36~43번 실제 화면 전환 영상](시안/36-43-창구-장면전환.mp4)

원본은 사용자가 제공한 접수창구 사진이며, 장면은 ChatGPT 내장 이미지 생성으로 제작했다. 가로·세로 이미지는 `public/scenes`에, 제작 의도와 장면별 지시는 [기획안](기획안.md)에 있다. 조선궁서체는 조선일보사가 배포한 원본 TTF를 사용한다. 압축 전송 시에도 복원되는 폰트 파일은 동일하다. [공식 배포 및 이용 조건](https://event.chosun.com/100/100font.html)
